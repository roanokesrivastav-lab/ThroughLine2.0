# Decisions

Judgment calls not settled by the brief, one line of reasoning each. Newest at the bottom.

1. **Next.js over Expo.** The build brief specified Next.js App Router + Vercel + Serwist; the later plan preferred Expo. The user asked to keep the original stack and take features from the plan, so Next.js it is. Going native later means a separate shell, not a rewrite of the engines, which are plain TypeScript.
2. **Serwist via the webpack bundler.** `@serwist/next` is documented against webpack; `next dev --webpack` / `next build --webpack` is the supported path on Next 16. The service worker is disabled in development.
3. **Client-side data via route handlers + TanStack Query**, not server components with direct DB reads. One data path, easier caching and invalidation after writes, and the API doubles as the contract a native client would use.
4. **Shared catalog is written only with the service role.** `media_items` is readable by any signed-in user and written by server code, so users cannot corrupt each other's metadata. Everything user-owned is RLS-scoped by `user_id`.
5. **One entry per user per media item.** Re-listens and re-reads are captured as additional reactions and resurfacing responses, not duplicate entries. Keeps history and phases honest.
6. **Extraction queue = a pending row + `after()` + daily cron.** No external queue. Saves return immediately; extraction runs after the response and any failures are retried by the cron with an attempt cap.
7. **Vocabulary v1** has five tag groups (tone, register, texture, aftertaste, theme) and three scalars (intensity, ache, pace). Themes and aftertastes carry the most weight in similarity because they bridge media best; register and texture are secondary.
8. **Deterministic mock extractor is a lexicon**, not a random stub, so the app is genuinely usable without an API key and results are explainable. The Claude extractor uses structured output against the same Zod schema and the same vocabulary.
9. **Claude model defaults to `claude-opus-5`** (the current guidance default), with `ANTHROPIC_MODEL` as an override for cost. Effort is set to `low` for both extraction and explanation because the tasks are small.
10. **Canon list is hand-written** (about 100 titles) with an `encounter_weight` used only to order onboarding cards and a faint `feel_prior` so a "Loved it" tap already carries signal. Priors are blended at low weight and always lose to the user's own words.
11. **Recommendation candidates come from three popularity-free sources:** the user's own backlog, the canon list (which carries priors), and other works by creators of things they loved (structural bridge, inherits a faded version of the loved entry's vector). No "people also liked", no trending, no discover-by-popularity.
12. **Private score weight in scoring is capped at ±0.05**, as a sort nudge on the bridge anchor only. Tests assert this.
13. **Books and time budgets.** A reading session is flexible, so books pass any budget ≥ 40 minutes and are excluded below that; "short to read" excludes books over roughly 300 pages (1.6 min/page heuristic).
14. **Phases are reconciled by fingerprint.** Re-detection updates existing phases and keeps user labels; phases that stop holding are deleted unless renamed. Confidence maps to tentative / likely / strong in the UI.
15. **Seasons are northern-hemisphere** in phase labels ("Winter 2025"). Easy to revisit.
16. **Feeling clusters need ≥4 loved entries in 60 days, ≥3 agreeing on a dominant attribute** and at least half the window. Labels are "Season Year: noun and noun".
17. **Resurfacing anti-annoyance:** no entry surfaces twice within 30 days, no push while a card is unanswered (14-day window), snooze respected, cadence off by default until opt-in, and the home card is pull-based so the feature works without push.
18. **Home recommendations are cached for 24h** in `query_sessions` (kind `home`) keyed by library size, so the AI explainer is not called on every visit.
19. **External scores are fetched only on an explicit tap** in entry detail, via an adapter method; never on render, never in lists.
20. **Demo library is seeded into the signed-in user's own account** from Settings (idempotent), rather than a separate demo account, so RLS and the real code path are exercised.
21. **Onboarding "Loved it" creates a completed entry with a `loved` reaction dimension and no note**; "Seen it" creates a completed entry with no reaction; "Never heard of it" is recorded only in `onboarding_prefs` so the card does not come back.
22. **`/search` redirects to `/add`.** One logging surface is less to learn.
23. **A rule-based tag baseline ships before the semantic attribute engine.** Founder's call: judge a simple, readable engine against real use first, then layer the sentiment matching on. `docs/RECOMMENDATIONS.md` §1–§12 becomes Stage 1.5.
24. **Tags are derived from taps, not declared in a form.** The original proposal was a preferences questionnaire. Genre tags cannot bridge media, so a declared-genre engine structurally cannot produce the product's signature line, and a setup form contradicts "low friction beats completeness". The onboarding canon pass already yields a weighted tag and creator profile on day one, from taps. Pinning and muting in Settings are the only declared inputs and both are optional.
25. **Tag specificity, not a binary stoplist.** A shared "indie folk" says far more than a shared "rock", so tags carry a 0..1 specificity used at match time. Only genuinely empty tags ("drama", "fiction", "classic") are dropped outright. Phase detection now shares this via `isTooBroadForPhases`, replacing its own hardcoded list.
26. **Tag families are walked one level only.** "indie folk" credits "folk" at 0.6. Walking further compounds the decay into noise, and the parent graph is hand-written and shallow on purpose.
27. **Overlap is coverage × confidence.** Coverage is the specificity-weighted mean of how much the profile likes the candidate's own tags, already a true 0..1 reading. Confidence rises with the number of distinct matches from a 0.65 floor. An earlier saturating-sum formula scored a good single-tag match at 0.10, which made the tag layer inert; this was caught by reading real engine output, not by a test.
28. **The rules/feeling blend is weighted by evidence, not fixed.** `feelingWeight(notes)` runs 0.15 at zero notes to 0.80 at twelve. The tag layer leads at cold start and recedes on its own as the user writes. This is what makes the baseline a seam rather than a dead end.
29. **The route is derived from whichever component dominated**, never chosen by hand, so an explanation cannot claim a reason the arithmetic did not support.
30. **Components re-normalise over the ones with evidence.** A candidate the feeling layer cannot read (most live catalogue results, which have no extracted attributes) would otherwise be structurally capped below the hand-written canon, quietly making the engine canon-only.
31. **Taste prefs live in `users.onboarding_prefs.taste`, with no migration.** Migration 0001 has not yet been run against a live project; adding 0002 before the first is exercised is premature. If the dismissed list outgrows a jsonb blob, that is the signal to promote it to a table.
32. **"Not for me" is item-scoped and never widens.** It hides that one candidate. It does not penalise the creator, the genre or the kind, because one rejection is not evidence about a whole category of things.
