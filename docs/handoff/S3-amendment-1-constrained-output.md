# Session 3, amendment 1: constrained JSON output on NVIDIA (handoff for GLM 5.3)

**Status:** founder-approved 2026-09-23. This amends `docs/handoff/S3-canon-profiles-qa.md`. Everything in that plan still applies unless this file overrides it.
**Continue in the same uncommitted working tree. Do NOT commit.**

## Why
The smoke run got 0 valid drafts in 51 calls (`docs/qa/session3-smoke-findings.md`). The root cause is that the NVIDIA path never constrains the output shape. It asks for JSON in prose and parses whatever comes back. The Claude path uses structured output and can't drift this way. Nemotron is a reasoning model, and it improvises a new JSON dialect on each run. The fix is to constrain decoding with the schema we already validate against, not to repair drafts afterwards.

The same unconstrained path does v2 note reading (`nvidiaReadingDraft`). No v2 NVIDIA reading has ever been stored (live rows are all `v1 | mock`), so fixing it now costs nothing, and it prevents the same failure when the founder later presses "Re-read my notes".

## Founder rulings in this amendment
1. **Remove the dialect normalizer** (`normalizeDraftDialect` in `nvidia.ts`) and any test that exists only for it. Malformed drafts are rejected, never repaired (DECISIONS #65).
2. **`PROFILE_SYSTEM_PROMPT` and `READING_SYSTEM_PROMPT` may change in this amendment only**, and only as §B describes. `PROFILE_VERSION` stays `p1` and `VOCABULARY_VERSION` stays `v2`. No p1 profile and no NVIDIA v2 reading has ever been persisted anywhere, and the cache's `prompt_hash` already invalidates the 51 failed entries.
3. **The call budget continues from the ledger** (51 used, 449 left). The 500 cap is unchanged.
4. **The default model stays Nemotron** (`NVIDIA_MODEL`). This amendment doesn't authorize switching it (DECISIONS #46). See §C for what to do if Nemotron can't be constrained.
5. **Strict gates.** Run only the script the current step names. `qa:repeat` runs only after a full canon run that passed the §7 gates. The 51-call smoke overrun must not repeat.

## A. Constrained output in `complete()`
- Add an optional `format` argument: `complete(system, user, maxTokens, format?: { name: string; schema: z.ZodType })`.
- When `format` is given, send the JSON Schema generated by `z.toJSONSchema(format.schema)` (Zod v4, already installed; no new dependency), using the **mode the probe (§C) selected**. The mode is stored as one constant, `NVIDIA_JSON_MODE`, of type `"response_format" | "guided_json" | "none"`:
  - `response_format`: `response_format: { type: "json_schema", json_schema: { name, schema, strict: true } }`
  - `guided_json`: `nvext: { guided_json: schema }`
- If the endpoint rejects the schema over unsupported keywords, strip **only** `maxItems`/`minItems` from the *sent* copy. Local `ProfileDraftSchema`/`ReadingSchema` parsing still enforces every cap. Record this if you do it.
- If the probe shows that turning off thinking makes constrained output reliable, pass the toggle the probe proved works (for example `chat_template_kwargs: { enable_thinking: false }`). Use it only for these two calls, and record it.
- `nvidiaProfileDraft` and `nvidiaReadingDraft` pass their schema. `nvidiaExplainer` is unchanged.
- Parsing stays strict: `json(raw, Schema)`. A schema failure is still a failure.
- 503 and timeout errors keep their current behaviour: they count as failed attempts, and `withRetries` handles them within budget.

## B. Prompt shape rules (both prompts)
Append a short section to each prompt, generated from the constants rather than typed out by hand:
- Every tag is exactly `{"key": <one listed value>, "weight": 0..1, "confidence": 0..1}` for profiles, and `{"key", "weight"}` for readings. It's never a bare string, and the field is never called `value` or `name`.
- Every group is an array, even when it has one item or none (`[]`). `story`, `feeling`, `scalars`, `craft` are always present as top-level keys.
- **One minimal worked example** of the full top-level shape, with one entry per non-empty group and `[]` elsewhere. Use real listed keys. For profiles, the example premise is neutral and names no real work.
- "Return only the JSON object: no prose, no code fences."

Don't change any word list, cap, weight rule or completeness rule.
